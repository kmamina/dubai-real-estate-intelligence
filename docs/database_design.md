# Database design (v1)

Database: `DubaiRealEstate` on SQL Server. Four schemas, seven tables.

```
CSV  --Python cleaning-->  raw.transactions   (original text, audit copy)
                           stg.transactions   (typed, cleaned, emptied every run)
                                 |  MERGE with joins + duplicate check
                                 v
                           core.dim_area   core.dim_property
                                 \             /
                                  core.fact_transactions  -->  SQL views  -->  Power BI
ops.pipeline_runs  (one row per run)    ops.dq_results (quality metrics per run)
```

| Schema | Table | Purpose |
|---|---|---|
| raw | transactions | Every CSV column stored as text, plus run id, file name and row number. Proof of what arrived. |
| stg | transactions | Landing area for cleaned, typed rows. Emptied each run. |
| core | dim_area | One row per area (268 expected). |
| core | dim_property | One row per property type and subtype, with business category. |
| core | fact_transactions | Cleaned transactions with KPI flags. Source for all reporting views. |
| ops | pipeline_runs | Execution log: start, end, file, status, row counts. |
| ops | dq_results | Data-quality metrics for each run. |

## Key decisions
- **Raw is text.** Loading can never fail on a bad value, and the original is preserved.
- **Surrogate keys** (`transaction_key`, `area_key`, `property_key`) are generated by the database. The CSV has no reliable unique row ID: transaction numbers repeat and 463 rows are fully identical.
- **`row_hash`** is a SHA-256 fingerprint of a row (plus its occurrence number among identical rows). A unique index on it stops the same row loading twice, even when a later CSV overlaps an earlier one. ASSUMPTION: DLD files are cumulative extracts; I have not verified this.
- **`file_hash`** in `pipeline_runs` stops the same file being loaded successfully twice.
- **Windows Authentication**, so no password is stored in code or in Git.
- Reserved words avoided: `usage` is `usage_type`, `procedure` is `procedure_name`.
